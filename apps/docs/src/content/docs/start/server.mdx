## What Porter adds

| Route                    | Purpose                                       |
| ------------------------ | --------------------------------------------- |
| `POST /porter/login`     | Creates or joins a room and issues the Token  |
| `HEAD /porter/rooms/:id` | Tells whether a room exists                   |
| `GET /porter/events`     | Opens a connection over SSE                   |
| `POST /porter/commands`  | Client messages for a User connected over SSE |
| `/porter/ws`             | Opens a connection over WebSocket             |

The paths are fixed. The four HTTP routes sit under your global prefix or `RouterModule`; `/porter/ws` ignores the prefix. With `app.setGlobalPrefix('api')`, the login is at `/api/porter/login` and the WebSocket is still at `/porter/ws`. That is why the client takes [two addresses](/porterkit/start/client/).

Both transports are always on; there is no option to switch one off.

## When the application does not start

Porter checks its configuration once, when the application boots, and refuses to start on any of these:

- an option with an invalid value (see [Configuration](/porterkit/reference/configuration/));
- two Managers for the same Game;
- a Game with a `tickRate` whose Manager has no `onTick`, or the reverse;
- an `initialGame` that names no registered Game, or no Manager registered at all.

The error names the option, the Game or the classes involved.
